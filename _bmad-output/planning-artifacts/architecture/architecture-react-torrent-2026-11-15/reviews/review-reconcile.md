## 判決

底稿把「帳密、閘門、資料來源、設定檔」這幾根大樑定得很清楚，但輸入裡有一批安靜的需求沒落地，其中 8 條會讓兩個 story 做得不一樣，或做出來達不到規格。最急的三條：AD-9 會把「連不到家裡」誤判成「Cloudflare 登入過期」；批次操作每筆各自成敗跟 AD-9「錯誤只有一種形狀」互相打架；容器只用一個 qBittorrent SID，電腦和手機同時開時 `rid` 增量會失效，每 5 秒都拿全部 4165 個種子。

嚴重度：
- **高**：不補的話，分開做的 story 會各做各的，或做出來跟 EXP 寫的不一樣。
- **中**：寫 story 時大概會補到，但沒寫進底稿就容易各補各的。
- **低**：措辭、範圍或驗收條件，影響小。

## 高

### R-01：不是 JSON 一律當 Cloudflare 過期，會吃掉「連不到家裡」

- **輸入**：EXP「State Patterns」表的「Cloudflare 登入過期」列：「不能跟『連不到家裡』寫成同一句，修法不同。」同表「連不到家裡（在外面時通道斷了、NAS 關了、手機沒網路）」；EXP「Foundation」：「設計要顧到：網路慢、連不到家、Cloudflare 登入過期。」
- **底稿**：AD-9「收到 HTTP 401 或不是 JSON 的回應，一律當成 Cloudflare Access 過期。」
- **問題**：在外面時，NAS 關機、cloudflared 掛掉或 react-torrent 容器沒起來，Cloudflare 回的是它自己的 HTML 錯誤頁（502、530 一類），不是 JSON。照 AD-9 會顯示「Cloudflare 登入過期了」加「重新登入」，按了只會重新整理，修不好。這正好是 EXP 說不能混在一起的兩種情況。反過來，Access 過期如果是轉址到另一個網域的登入頁，`fetch` 會因為跨來源直接丟錯，前端會當成網路斷了。另外「Access 看到 `X-Requested-With` 就回 401」是底稿的前提，這次沒查證。
- **建議**：改 AD-9 的分類規則，寫成一張表：
  - HTTP 401 → Cloudflare 登入過期
  - HTTP 200 但內容是 HTML（跟著轉址拿到 Access 登入頁）→ Cloudflare 登入過期
  - `fetch` 丟錯、瀏覽器端逾時、HTTP 5xx（含 Cloudflare 的 502、503、504、52x、530 HTML 頁）→ 連不到家裡
  - JSON 的 `{ code, message }` → 照 code 表
  另外在先不決定或 story 驗收裡加一條：上線前在 Tunnel 網址實測 Access 過期時，帶 `X-Requested-With` 的請求到底回什麼。
- **嚴重度**：高

### R-02：批次操作每筆各自成敗 vs 一種錯誤形狀

- **輸入**：
  - EXP「新增種子 add-torrent」：「常常一次貼很多筆，所以貼上後大框變成清單，一筆一列」；「動作成功時」表的新增列：「有幾筆被 qBittorrent 拒絕：成功的從清單消失，失敗的留著，那一列寫原因」「5 個加好了，2 個失敗」。
  - EXP「State Patterns」的「多選動作部分失敗」：「3 個刪好了，2 個失敗」「改路徑是『3 個開始搬了，2 個失敗』」「每列名稱下面一行 `status-error` 的原因」「重試 2 個」。
- **底稿**：AD-9「server function 失敗一律是 `{ code, message }`」，只有整個函式成功或失敗。功能對應只寫 `addTorrents`、`deleteTorrents`、`setLocation`。
- **問題**：一個函式一個錯誤，表達不了「8 筆裡 2 筆失敗、各自原因」。qBittorrent 這邊，`torrents/add` 一次送好幾筆時只回整批一個結果；`torrents/delete` 不管 hash 存不存在都回 200。不先定好，新增、刪除、改路徑三個 story 會各自發明一種部分成功的格式，有的在瀏覽器裡迴圈呼叫，有的在容器裡迴圈。
- **建議**：新 AD「批次操作回每筆結果」：
  - 批次的 server function（`addTorrents`、`deleteTorrents`、`setLocation`、改檔名，見 R-15）成功時回 `{ results: [{ id, ok, code?, message? }] }`，`id` 是 hash 或新增清單裡那一列的編號，`code` 用 AD-9 的表。只有整批都做不了（沒登入、連不到 qBittorrent）才走 AD-9 的整體錯誤。
  - 迴圈放在容器裡，一筆一個 qBittorrent 請求，前端不自己迴圈。
  - 刪除成不成功，用之後的 `maindata` 有沒有那個 hash 來確認，寫清楚以哪個為準。
  - AD-9 加一句：批次的部分失敗不算「失敗」，不走 `{ code, message }`。
- **嚴重度**：高

### R-03：一個 qBittorrent SID 給多個瀏覽器，`rid` 增量失效

- **輸入**：EXP「Foundation」：「規模：約 4165 個種子」；EXP「排序和檢視」：「排序記在 NAS 上，電腦和手機共用」；EXP「Foundation」：「電腦和手機都會用」。手機在行動網路上用（EXP「在哪裡用」）。
- **底稿**：AD-4「SID 只在容器記憶體」（一個 SID）；AD-6「每 5 秒呼叫 `getMaindata(rid)`，用 qBittorrent 的 `rid` 增量合併」，合併在前端。
- **問題**：查了 5.1.4 原始碼：`SyncController` 是在 `WebApplication::sessionStart()` 時每個 session（SID）各建一個；`maindataAction` 只在傳進來的 `rid` 等於這個 session 上次送出的 id，或上次確認過的 id 時才給增量，其他情況 `full_update` 是 true。容器只有一個 SID，電腦、手機、兩個分頁輪流帶自己的 `rid` 來，每次都對不上，結果每 5 秒都拿到全部 4165 個種子的完整資料，手機走行動網路經過 Tunnel 也一樣。只開一個瀏覽器時不會發生，所以開發時看不出來。
- **建議**：改 AD-4 和 AD-6，二選一寫死：
  1. 容器自己每 5 秒向 qBittorrent 拿 `maindata`（一條 `rid` 鏈），在容器記憶體合併成完整資料；瀏覽器向容器拿，容器用自己的版本號給增量，或直接給瘦身過的完整資料（見 R-12）。
  2. 容器替每個 App 登入 session 各開一個 qBittorrent SID。
  第 1 種比較簡單，也只有一個地方碰 qBittorrent，建議用它。AD-6「只有一個地方抓」的意思就從「前端一個 query key」變成「容器一個輪詢」，前端照樣只有 `['maindata']` 一個 key。
- **嚴重度**：高（原始碼已讀；實際流量沒在 NAS 上量過）

### R-04：畫面狀態放哪沒定

- **輸入**：
  - 根目錄 `DESIGN.md` 設計要求 2：「『共幾個』是目前篩選後的列表有幾個」；EXP「detail-header」：「M 是目前篩選後的數量」「看板模式的範圍是『這一欄』」。
  - EXP「刪除確認」：「照勾選的先後排，最早勾的在最上面」。
  - EXP「排序和檢視」：「資料一直更新時先不重排……電腦滑鼠停在列表上；有勾選任何一個；手機手指正在捲，或底部面板開著。情況結束後才重排一次，正在看的那一列的內框跟著那個種子走。」
  - EXP「State Patterns」的「正在看的種子不見了」：「詳情換成補上它位置的那一列（原本的下一個）」。
  - EXP「Interaction Primitives」：「換分類、改搜尋關鍵字時清掉選取」。
- **底稿**：AD-6 只定種子資料來源；功能對應把列表、看板、詳情、刪除、改路徑分成不同 feature 資料夾，但沒說這些 feature 共用的畫面狀態放哪。
- **問題**：「正在看哪一個」「已選哪些（有先後）」「目前篩選加排序後的順序」「凍結中的順序」「搜尋關鍵字」至少被列表、看板、詳情固定頭、選取列、刪除確認、改路徑、快捷鍵七個地方同時讀寫。不先定，會出現詳情的「第 N 個」用即時順序、列表用凍結順序，數字對不上；或刪除確認拿到的是沒有先後的 Set。
- **建議**：新 AD「畫面狀態只有一份」：
  - 哪些放網址（TanStack Router search params）：目前分類、正在看的 hash、搜尋關鍵字。好處是 R-11 登入後回原畫面直接帶網址回去。
  - 哪些放一個前端 store：選取（有順序的陣列，記勾的先後）、凍結的順序快照、目前是否凍結。
  - 「篩選加排序後的順序」只由 `src/lib` 一個純函式從 `['maindata']` 加上面這些狀態推出來，列表、看板、詳情固定頭、快捷鍵都用它。
  - 寫明換分類、換搜尋時誰負責清選取。
- **嚴重度**：高

### R-05：「上次看的分類」「每分類上次看的種子」「自動收合開關」存哪

- **輸入**：
  - EXP「排序和檢視」：「打開 App 回到上次看的分類，加上那個分類記住的排序」（memlog #46）。
  - EXP「detail-panel」：「剛打開、換分類或換排序時，先顯示這個分類上次看的那個，沒有就顯示第一個，跟排序一樣每個分類各記各的」（memlog #59）。
  - EXP「Information Architecture」設定頁：「『捲動時自動收合其他欄』開關，預設開……手機上照樣顯示，旁邊一行……『只在電腦版有用』」。
  - EXP「登入」：「登入後回到原本的畫面和分類……照『打開 App 回到上次看的分類』」。
- **底稿**：AD-8 綁的只有「排序記憶、分類順序、常用路徑」，memlog E 列的內容也只有這三樣。
- **問題**：這三樣沒有歸屬。一個 story 放 localStorage、另一個放 settings.json 的機會很高。「手機上照樣顯示開關」暗示它是共用的設定；「上次看的分類」要不要跨裝置 EXP 沒寫明，但「跟排序一樣每個分類各記各的」的那句是比照排序（排序是存 NAS 共用）。
- **建議**：改 AD-8，把設定檔內容列成完整清單，每一項標「共用（settings.json）」或「這台裝置（localStorage）」：
  - 共用：每分類排序（含方向）、分類順序、常用路徑（含媒體庫勾選）、自動收合開關（建議共用，因為設定頁兩邊都顯示）。
  - 待 Alex 選：上次看的分類、每分類上次看的種子。建議放這台裝置，因為手機和電腦同時開時共用會互相跳；但這是體驗取捨，要問 Alex，不能代決。
  - 修改函式補 `setBoardAutoCollapse`，以及如果選共用，補 `setLastCategory`、`setLastViewed`。
- **嚴重度**：高

### R-06：EXP 要沿用舊設定頁，舊頁會改 qBittorrent 設定

- **輸入**：EXP「Information Architecture」：「沒有新的設定畫面，沿用 App 原本的設定頁（`src/routes/settings.tsx`），樣式照現有的列，不畫」。EXP「State Patterns」：「用 repo 現有的 toast」；EXP「Foundation」：「shadcn/ui（repo 已裝）」。
- **底稿**：memlog 大決定 3「舊 src 整個換掉，同 repo 新寫」；AD-5「`app/setPreferences` 和其他改 qBittorrent 設定的 API 一律不開」；「結構／原始碼」的 features 清單是 list、board、detail、add、delete、path、rename、login，沒有 settings。
- **問題**：查了舊程式，`src/components/settings/` 有 speed、bittorrent、connection、webui、advanced 等分頁，用 `useUpdatePreferences` 改 qBittorrent 偏好設定，也有讀 `localStorage` 的 `qbit_baseUrl`。「沿用」照字面做就違反 AD-5 和大決定 3。另外 features 清單少了 settings、搜尋、頁首（速度膠囊、提示條）、快捷鍵說明，做到時會不知道放哪。
- **建議**：
  - 底稿寫明：設定頁在新結構裡重寫，只放 EXP 要加的兩項（分類順序、自動收合開關），不放 qBittorrent 位址、帳密、任何 qBittorrent 偏好設定；外觀照 UX-DESIGN 的列樣式。
  - features 清單補 `settings`、`header`（速度、連線提示、搜尋框）、`shortcuts`。
  - 回頭在 EXP 加一句：「沿用」指的是位置和樣式，不是舊程式。toast 同理，用新專案的 shadcn toast。
- **嚴重度**：高

### R-07：搬移中要寫「正在搬到 <新路徑>」，qBittorrent 不給目標路徑

- **輸入**：EXP「詳情狀態區每種狀態寫什麼」的搬移中列：「最前面加『搬移中 · 正在搬到 <新路徑> · 』」「儲存位置區塊的按鈕先不能按，真的搬完才出完成的 toast」。EXP「動作成功時」改路徑（一個）：「真的搬完才出 toast『已搬到 影集媒體庫　接著改檔名』」。旅程 1 第 5 步。
- **底稿**：AD-7「操作成功後不自己改 `['maindata']`，立刻觸發一次 `getMaindata`」。沒有任何地方記「這個種子正在搬去哪」。
- **問題**：查了 5.1.4 `serialize_torrent.cpp`：搬移中只有 `state: "moving"`，`save_path` 等路徑欄位是目前位置，沒有搬移目標。要寫「正在搬到 /data/media/tv」和「搬完才出 toast」，App 必須自己記「hash → 目標路徑」，而且要偵測 `moving` 結束。記在瀏覽器記憶體的話，重新整理或在另一台裝置打開就沒有目標路徑、也不會出完成 toast；對話框關掉以後也要有人繼續看。
- **建議**：新 AD（或併入 AD-7）「搬移中由容器記」：`setLocation` 成功時容器在記憶體記 `hash → 目標路徑`，`getMaindata` 回傳時把目標路徑附在那個種子上，`moving` 結束後刪掉。完成 toast 由前端比對「上一份有目標路徑、這一份沒有」觸發，只在發起搬移的那台出。容器重啟遺失時，畫面退回只寫「搬移中」。如果覺得容器記太重，至少寫明「只在發起的那個分頁記，重新整理後只寫『搬移中』」，讓 story 不要各自猜。
- **嚴重度**：高

### R-08：在家走 http，剪貼簿和 `crypto.subtle` 用不了

- **輸入**：EXP「儲存位置區塊」：「『複製』複製完整路徑」，「複製路徑成功」列：「『複製』按鈕的字變成『已複製』1.5 秒」。EXP「新增種子」：「判斷重複用磁力連結的 btih、.torrent 檔的 info hash，一貼上就判斷」。旅程 1、2、4 都在電腦前。
- **底稿**：AD-2 定了在家用 IP 加 port 走 http（memlog：「http，跟 Tunnel 網域是不同來源」）。底稿沒提安全環境（secure context）限制。
- **問題**：瀏覽器的 `navigator.clipboard.writeText` 和 `crypto.subtle` 只在 https 或 localhost 才有。在家用 http 打開時，「複製」會沒反應，用 `crypto.subtle` 算 .torrent 檔 info hash（SHA-1）的寫法會直接壞。開發時用 localhost、在外面用 https，兩邊都正常，只有在家正式使用才壞，CI 抓不到。
- **建議**：一致性慣例加一列「不依賴只在 https 才有的瀏覽器 API」：複製要有退路（暫時的 textarea 加 `execCommand('copy')`），或在容器做不到時明寫在家不能複製；info hash 在容器算，或在 `src/lib` 用純 JS 的 SHA-1。驗收時要在家用 http 開一次。

### R-09：瀏覽器端沒有逾時；10 秒提示、30 秒失敗、逾時後重試

- **輸入**：EXP「State Patterns」送出中列：「送出超過 10 秒，按鈕下面多一行……『還在等 NAS 回應』；超過 30 秒算失敗」。「刪除、改路徑、改檔名失敗」列：「跳出原因和『重試』」。
- **底稿**：AD-9 的 `timeout` 是「對 qBittorrent 超過 30 秒」，只有容器到 qBittorrent 這段。
- **問題**：在外面時，慢的常常是手機到 Cloudflare 到容器這段。Tunnel 卡住時瀏覽器的請求可能一直不回，容器的 30 秒逾時救不到，按鈕會一直「刪除中…」而且對話框關不掉（EXP 規定送出中不能關）。輪詢也一樣，一個卡住的請求會讓「最後更新」一直不更新但又不算失敗。另外逾時不代表 qBittorrent 沒做：刪除重試會刪到已經不存在的、新增重試會被當重複拒絕，畫面要能接受。

### R-11：登入後回原畫面怎麼做

- **輸入**：EXP「登入」送出：「登入後回到原本的畫面和分類，開著的對話框不保留」。EXP「qBittorrent 登入過期」列：「App 自動重新登入，不顯示登入畫面」。

### R-12：4165 個種子的效能

### R-13：動畫不掉格 vs 每 5 秒資料更新；刪除淡出 vs AD-7

- **輸入**：根目錄 `DESIGN.md` 設計原則 1：「會掉格的動畫寧可不要」。EXP「動態」：「只動 `transform` 和 `opacity`」「進度環……要換成 SVG `stroke-dashoffset`」「要在真的手機上試」；看板自動收合：「第 2 步 1.3 秒」「整段動畫期間停住捲動」「FLIP」。EXP「動作成功時」刪除：「被刪的列淡出 0.2 秒，下面的列補上來」。
