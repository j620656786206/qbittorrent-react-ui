## E2E recommendation

**What happy-dom covers now.** Logic that needs a DOM but not layout: which rows the virtualizer renders when `clientHeight` is faked, that a poll re-renders only the changed row, mouse and finger freeze rules driven by synthetic events and a mocked `matchMedia`, unmount clean-up, retry double-press guard, focus moving to `main`, and the alert bar's live region (`src/features/list/torrent-list.dom.test.tsx:68,135,171-252`; `src/shared/ui/alert-bar.dom.test.tsx:55-74`).

**What only a real browser shows.** Real layout (row height, no horizontal scroll at 390 px, the 1024 px breakpoint), the real virtualizer DOM count and scroll smoothness with measured sizes, CSS behavior (dark mode via `prefers-color-scheme`, `:focus-visible` rings, 50% dim), CSP enforcement (the nonce on hydration, and the Radix `<style>` injection that R2 predicts), real focus order, and screenshots to compare with the mockups. Touch momentum timing on an iPhone is not reproduced faithfully by desktop emulation either; that stays on the NAS checklist ("手機捲動時不換位置").

**Options.**

1. Keep manual ego-browser checks only. No new dependency. Gaps P2 and P3 stay: every review-fix PR has shipped UI changes without a recorded browser re-run so far.
2. Vitest browser mode for component tests. Reuses vitest and gives real layout per component, but does not exercise the built server, the gate or the CSP nonce path, so it misses R2.
3. **Recommended: one browser smoke, Chromium only, in the PR CI job, against the built server plus `scripts/fake-qbit.mjs`.** One spec file with about five checks: log in and see rows (data `sample`); data `many`, scroll, assert the row elements stay bounded; zero `securitypolicyviolation` events and zero console errors across the run; 390 px width has `scrollWidth <= clientWidth`, with light and dark screenshots kept as CI artifacts for a human look (no pixel diffing); `front=cloudflare` shows the Cloudflare alert and retry moves focus to `main`. Cost: one exact-pinned dev dependency, a cached browser download in CI, one more CI step, and some flake risk that the fake server's deterministic modes keep small. It stays within AD-15 because it only talks to the fake qBittorrent, but `scripts/fake-qbit.mjs:2` says "never run in CI", so that line and the spine row change with it. This is the cheapest option that closes the deferrals the epic kept marking "browser only" (P3) and catches R2 before Epic 2 ships a dialog.
